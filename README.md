# SentinelML: Login Anomaly Detector

SentinelML is a Streamlit app for exploring login and event logs and identifying records that look unusual. It uses an unsupervised Isolation Forest model, so it can produce anomaly signals without a pre-labeled training dataset. The interface presents flagged records, risk levels, anomaly scores, and short explanations in a terminal-inspired dashboard.

> **Important:** SentinelML is a learning and triage aid, not a production security control. Review flagged events with domain context; an anomaly is not proof of malicious activity, and normal-looking events are not guaranteed safe.

## Features

- Upload CSV or JSON event logs.
- Preview the input and inspect inferred column roles.
- Exclude likely identifiers and existing binary anomaly/label fields from model features.
- Derive signals from numeric columns, timestamps, and categorical frequency.
- Run Isolation Forest detection with a configurable contamination setting.
- Review flagged records, risk levels, anomaly scores, and heuristic explanations.
- Filter flagged records and download results as CSV.

## Requirements

- Python 3.10 or later
- pip

The dependencies are listed in `requirements.txt`: Streamlit, pandas, NumPy, and scikit-learn.

## Run locally

From the repository directory, create and activate a virtual environment.

Windows PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

macOS or Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Streamlit prints a local URL, usually `http://localhost:8501`. Open it in your browser, upload a log file, review the inferred schema, adjust the contamination setting if needed, and run detection.

## Input data

Upload a `.csv` file or a `.json` file. CSV files should have a header row. JSON can be a list of event objects, or an object containing a list of event objects. Each object in the list becomes a row.

There is no required column naming convention, but useful event fields include timestamps, user or session identifiers, device, location, login result, failed-attempt count, and session duration. The detector infers column types, but review the preview because automatic inference can be wrong. Identifier-like fields are excluded from model features; recognized binary label/flag fields are also excluded to reduce label leakage.

## How detection works

1. The app reads the uploaded records into a pandas DataFrame.
2. The detector identifies likely identifiers, timestamps, numeric values, categorical values, and eligible binary labels.
3. Numeric values, time-derived signals, and frequency-encoded categorical values are assembled into a feature matrix and scaled.
4. Isolation Forest assigns anomaly scores and flags a portion of records according to the contamination setting.
5. The app displays flagged records and heuristic explanations, then allows a CSV export.

The contamination value is an estimate of the proportion of unusual records, not a measured probability that a record is malicious. Changing it changes the number of records the model flags. Explanations are heuristic signals, not explanations generated by the model itself.

## Troubleshooting

- If PowerShell blocks virtual-environment activation, use the Python executable directly after creating the environment: `.\.venv\Scripts\python.exe -m pip install -r requirements.txt` and `.\.venv\Scripts\python.exe -m streamlit run app.py`.
- If a CSV or JSON file fails to load, verify it is valid UTF-8 and that each JSON event is an object with consistent fields.
- If too many or too few records are flagged, adjust contamination and compare the results with known examples. Do not treat the setting as an accuracy control.
